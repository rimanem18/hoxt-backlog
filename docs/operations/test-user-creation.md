# テストユーザー作成手順（メールパスワード認証）

運用担当・QA 担当が、確認メールの受領を待たずにサインイン可能なテストユーザーを
作成するための手順を記載する。

## 1. Supabase Dashboard でのテストユーザー作成（REQ-106）

1. Supabase Dashboard にアクセスし、対象プロジェクトを開く
2. 左メニューの **Authentication** → **Users** を開く
3. **Add user** をクリックする
4. **Email** と **Password** を入力する
5. **Auto Confirm User** を有効化してユーザーを作成する

### 手動受け入れ確認（AC-04）

- 作成直後のアカウントで、確認メールのリンクを開かずにログイン画面から
  サインインし、成功することを確認する
- 一般のサインアップフォーム（`/signup`）から同じ操作を行っても、
  確認メールの送信を経ずにサインインできる状態は作れないことを確認する
  （通常のサインアップは常に「確認済み」以外の状態で作成され、
  確認メールのリンクを開くまでサインインが拒否される）

## 2. パスワードリセット後の旧パスワード無効化確認（REQ-105）

自動テストでは実際のメール受信・リンククリックを扱えないため、以下を手動で確認する。

1. 確認済みのテストアカウントで `/auth/forgot-password` からパスワードリセットを要求する
2. 受信したメール内のリンクを開き、新しいパスワードを設定する
3. 新しいパスワードでサインインできることを確認する
4. リセット前の旧パスワードで新規サインインを試み、拒否されることを確認する
   （技術設計上は Supabase が `updateUser` 完了時に既存セッションを失効させる
   想定だが、この手動確認では「旧パスワードでの新規認証が成立しないこと」を
   確認する。既存セッションが継続利用できてしまっていないかは、別途ブラウザで
   旧パスワードでのサインイン状態を保持したまま操作を試みて確認する）

## 3. セッション保護方針の同一性確認（NFR-103）

メールパスワード認証のセッションが、Google 認証と同一の保持期間・失効条件で
扱われていることを Supabase Dashboard 上で確認する。

1. メールパスワードでサインインする
2. Supabase Dashboard の **Authentication** → **Sessions** を開く
3. 作成されたセッションの有効期限・失効条件が、既存の Google 認証セッションと
   同一の設定（プロジェクト共通の JWT 有効期限設定）に従っていることを確認する
