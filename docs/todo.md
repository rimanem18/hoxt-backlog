# プロジェクト関連リンクをnext/linkに置き換える

現在プロジェクト一覧・最近のプロジェクト・プロジェクト詳細間の遷移は`<a>`タグによるフルページ遷移。`next/link`のクライアントサイド遷移に置き換え、プリフェッチによる体感速度向上を図る。

`taskSlice`の絞り込み・並び替え状態（`TaskFilter`/`TaskSort`）がプロジェクトIDに紐付かないグローバルなReduxステートのままだと、プロジェクトを跨いで条件が引き継がれてしまう問題がある（現状はフルページ遷移のたびにストアが初期化されるため顕在化していない）。このリンク差し替えと合わせて、以下いずれかの対応も行う。

- `taskSlice`のfilters/sortをprojectId単位でスコープする
- プロジェクト遷移時にfilters/sortをリセットする仕組みを入れる

# 閲覧者画面 リアクション

## ユーザーストーリー

1. 上長として、気になったタスクに軽くリアクションで反応を伝えたい。
2. 部下として、上長からの疑問に先回りして答えられるよう、優先度判断の根拠をタスクに残しておきたい。

## 要件定義

- viewerはタスクに絵文字リアクションを付けられる
- 優先度判断の根拠は新規フィールドとしては明示しない。既存のtask説明/メモ欄で代替可能

## 技術補足と制約

- **DBスキーマ変更**: `task_reactions` の追加

## スコープ外（今回は含めない）

- viewerのコメント機能（保留）
  - 判断材料: 現設計（`project_viewers` のトークンでviewerを識別）のまま `task_comments` テーブルを後付けするだけで済み、認証方式や識別の仕組み自体を作り直す必要はない
  - ただし後から追加する場合、以下は現設計に含まれていない新規要素になる
    - 自由記述の書き込みに対する乱用対策（レート制限・文字数制限など）。リアクションは選択式のため不要だったチェックが新たに要る
    - コメントが付いたことを部下側に知らせる通知経路（現設計の通知は「更新→viewer」の一方向のみで、「viewer→部下」の逆方向は未設計）
- スレッド型コメント、既読管理の詳細
