1. `@knowledge` ディレクトリを確認して、関連する情報を収集してください。knowledge にはフロントマターがあるものもあるため、まずは必要かどうかそこで見極めて読みます。
2. 次に、課題を解決するために、Explore サブエージェントでコードベースを調査します。メインエージェントが調査する必要はありません。（必要性があれば、複数起動してもよいです）
3. サブエージェントから応答がきたら、計画の草案を立ててください。3つ以上提案して統括後、最も推奨する案に関しては、それを明示してください。

## 実施フェーズ

ユーザーによってどの計画に基づいて対処するか決定されたら、対応を開始してください。

1. 計画に基づく課題の解決をしてください。

- コード変更が必要な場合は、まずは仕様を明確にして TDD 開発サイクルで解決します。

2. 解決後、 Code review サブエージェントにレビューを依頼してください。このとき、以下を伝えてください。
   - レビューの観点を明確に伝えるための変更内容とレビューしてほしいポイント
   - メインエージェントで十分なテストをしているため、ビルドやテストはせずにコードベースのレビューをしてほしい旨
   - 異常系・境界値テストが不足していないか
   - 言語やフレームワークの慣習や流儀に従えているか。もしも齟齬がある場合、プロジェクトが提示するガイドライン（\*.instructions.md や AGENTS.md）がそもそもおかしくないか確認し、ガイドラインがおかしい場合は修正案を提示してほしい旨

3. その後、 `/resolve-feedback` Skill を使用してください。妥当性の高い指摘があるか確認します。
