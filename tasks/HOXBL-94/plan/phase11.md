### 設計との差異・環境不具合の対応

1. **重大な環境不具合を発見・修正**: E2E 実装中、フォーム送信の `onSubmit` が一切発火せず、ネイティブ HTML フォーム送信（フルページリロード）になってしまう現象を確認。調査の結果、Docker Compose 環境でブラウザが `http://client:3000` としてアクセスする際、Next.js dev サーバーの DNS リバインディング対策（Origin 検証）が `client` ホストを信頼せず、HMR WebSocket ハンドシェイクが破損 → React のハイドレーション自体が完了しない、という環境起因の不具合だった。
   - 対応: `app/client/next.config.ts` に `allowedDevOrigins: ['client']` を追加
   - 対応: `compose.yaml` の `NEXT_PUBLIC_TRUSTED_DOMAINS` に `http://client:${CLIENT_PORT}` を追加（パスワードリセットの `redirectTo` オープンリダイレクト検証が `client:3000` を信頼済みと認識できず失敗していたため）
   - いずれも dev 専用設定であり、本番・preview 環境の `NEXT_PUBLIC_TRUSTED_DOMAINS` や `next.config.ts` の `output: 'export'` ビルド挙動には影響しない
2. **Codex レビュー指摘への対応**:
   - サインイン成功テストに `ダッシュボード` 見出しの表示確認を追加（URL 遷移のみでは AuthGuard 以降の描画不能を検知できないため）
   - サインアップのメール表記揺れテストを、常に 409 を返す素朴なモックから、送信された email を正規化した値で照合するモック（`mockEmailSignupConflictForNormalizedEmail`）に変更し、フロントエンドが入力値を加工せず送信することを検証する契約寄りのテストに強化
   - 運用ガイドの「Supabase が既存セッションを失効させる」という断定的な記載を、手動確認手順として検証可能な表現に修正
3. **DCQ-03（Supabase Auth ダッシュボードのリダイレクト URL 許可リストへの `/auth/reset-password`, `/auth/confirm` 登録）は、実際の Supabase プロジェクト（preview/production）に対する手動のダッシュボード操作であり、本セッションのコード変更では対応不可。リリース前チェックリストとして引き続き未消化。
