# HOXBL-94 ヒアリング記録

## メタ情報

- **Requirement ID**: HOXBL-94
- **対象機能**: メールパスワード認証の追加
- **ヒアリング目的**: 業務要件の抽出と、技術設計に引き継ぐ論点の識別

## Q&A

### Q1. 対象機能の概要

- **質問**: HOXBL-94 はどのような機能・対象を扱う要件ですか？
- **回答**: Google OAuth 認証だけでなく、メールパスワード認証を追加したい。Google アカウントを持っていなくても使用できるようにしたい。

### Q2. 主な利用者

- **質問**: この機能の主な利用者は誰ですか？（複数選択可）
- **回答**:
  - Google アカウントを持たない一般ユーザー
  - テスト・検証用ユーザー

### Q3. 受け入れ基準（成功状態）

- **質問**: この機能で「これができたら成功」と言える状態はどれですか？（複数選択可）
- **回答**:
  - メール+パスワードで新規登録・ログインできる
  - Google 認証とメール認証が並存できる
  - パスワードリセットができる
- **補足**: 「確認メール」は当初選択されなかったが、Q5 にて「一般ユーザーは確認必須／テストユーザーは管理者経路で確認スキップ」に決定。

### Q4. 同一メールアドレス時の扱い（アカウント同一性）

- **質問**: 同じメールアドレスを Google とメールパスワードの両方で使うケースをどう扱いますか？
- **回答**: 同じメールは同一ユーザーとして統合したい。

### Q5-a. 認証基盤

- **質問**: 認証・会員管理の基盤について、現状の認識と今回の方針はどちらですか？
- **回答**: 現状の Supabase Auth をそのまま使う。

### Q5-b. 確認メール（事前質問）

- **質問**: メールパスワードで新規登録するとき、メールアドレスの本人確認（確認メール）は必要ですか？
- **回答**: `test@example.com` のような検証用メールアドレスが登録できないのは困る。確認なしで Supabase に直接登録できる方法があるか確認したい。
- **回答（補足対応後）**: 一般ユーザーは確認必須 / テストユーザーは管理者経由で確認スキップ。

### Q6. パスワード要件

- **質問**: パスワードの要件（最低長や複雑さ）はビジネスとして指定がありますか？
- **回答**: 未決事項にして技術設計へ委ねる。

### Q7. ログイン失敗時メッセージ

- **質問**: ログイン失敗時のメッセージの見せ方は？（セキュリティと UX のトレードオフ）
- **回答**: 原因を区別しない「メールアドレスまたはパスワードが間違っています」というメッセージ。

### Q8. パスワードリセットリンクの有効期限・回数

- **質問**: パスワードリセットリンクの有効期限・使用回数に「業務上の期待」はありますか？
- **回答**: Supabase のデフォルトに任せる。

### Q9. ログイン画面のレイアウト

- **質問**: ログイン画面の見せ方はどうしますか？
- **回答**: 1 つのログイン画面に Google ボタンとメールパスワードフォームを並べる。

### Q10. ブルートフォース対策

- **質問**: ブルートフォース対策（連続失敗時のロック / レート制限）に業務要件はありますか？
- **回答**: Supabase のデフォルトに任せる。

### Q11. セッション保持期間

- **質問**: ログアウト・セッション保持期間は、既存の Google 認証と同じ振る舞いでよいですか？
- **回答**: 同じ振る舞いでよい。

### Q12. 同一メール衝突時の UX

- **質問**: Google で登録済みのメールで「メールパスワード新規登録」を試みたとき、ユーザーにはどう見せたいですか？
- **回答**: 「このメールは Google で登録済み。Google でログインしてパスワード設定してください」と伝える。

## ヒアリングから派生した未決事項（すべて解消済み）

- OQ-01（解消）: パスワードポリシー → 大文字・小文字・記号含む 8 文字以上、Supabase Auth ダッシュボードで設定。
- OQ-02（解消）: 未確認アカウントのサインイン試行時 → 案内メッセージのみ、再送 UI はスコープ外。
- OQ-03（解消）: Google ユーザー向けパスワード追加設定画面は別タスクで担保されない。案内文（REQ-302）での誘導にとどめ、実設定画面はスコープ外。
- OQ-04（解消）: 既存のメールテンプレートを利用。将来のカスタマイズはスコープ外（後続タスクに委ねる）。

## 追加ヒアリング（要件定義後）

### QA-1. REQ-303 の再送 UI の有無

- **質問**: 未確認アカウントでのサインイン試行時、確認メール再送 UI を実装するか。
- **回答**: 案内のみ。

### QA-2. パスワードポリシー

- **質問**: パスワードの強度要件。
- **回答**: Supabase ダッシュボードで設定する。大文字・小文字・記号を含む 8 文字以上。

### QA-3. Google ユーザー向けパスワード追加導線（OQ-03）

- **質問**: 設定画面などで「パスワード追加」機能の担保が別タスクにあるか。また REQ-302 のメッセージニュアンスの確認。
- **回答**: 担保されない。メッセージは「設定してください」という命令的なニュアンスではなく「Google ログインのままでも使えます。パスワードでも使いたい場合は設定できます」という案内調にしたい。

### QA-4. メール文言テンプレート（OQ-04）

- **質問**: 確認メール／パスワードリセットメールの既存テンプレートはあるか。
- **回答**: 既存テンプレートあり。将来的にカスタマイズする可能性はあるが今回はスコープ外。
